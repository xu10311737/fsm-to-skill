# 当 Skill 变得复杂，我开始怀疑大模型：直到我遇到了「状态机」

> 一个前端仔 + Python 后端，在折腾 AI Agent Skill 的路上，被一个叫 **fsm-to-skill** 的开源项目刷新了认知。如果你也被"越写越大的 Skill""越调越乱的流程"折磨过，这篇文值得你花 5 分钟看完。

---

## 一、先说件事：我为什么越写 Skill 越心累

事情是这样的。半年前我开始用各种 Agent 做自动化。一开始很爽——几条 Prompt 就能让模型帮我干活。但慢慢地，任务开始变复杂了。

比如我要让 Agent 做这么一件事：**从一批文件里，每个文件提取关键信息 → 分类 → 汇总成表格 → 输出报告**。听起来很简单对吧？

于是我开始在 `SKILL.md` 里写：

1. 第一步，读取文件；
2. 第二步，如果文件是 PDF 走 A 流程，如果是 Excel 走 B 流程；
3. 第三步，对提取结果去重、合并；
4. 第四步，判断有没有异常，有就再查一遍；
5. 第五步，汇总……
6. 第六步，如果上面某一步失败了，重试；
7. 第七步，……

写着写着，这份 Prompt 就变成了几百行。我盯着屏幕，越看越觉得不对劲。

### 1. 流程失控与"幻觉"

Skill 一旦复杂，模型就开始"自由发挥"。明明我在 Prompt 里写死了"先做 A 再做 B"，它偏要先做 B 再回来做 A。批评它两句，它改了，但下次又犯。

更可怕的是**奖励黑客**——模型会偷偷跳过让它觉得"麻烦"的步骤，只为了赶紧把结果交出来。它以为自己在帮忙，其实在偷懒。

### 2. 维护成本爆炸

几百行的 Prompt，没有逻辑边界。今天业务改了，我想在"分类"这步之前加一个"过滤"步骤。我哆哆嗦嗦地找半天，终于塞进去了。结果呢？模型理解错了，流程全乱了。

**AI 越改越费力，Skill 越改越庞大**。这简直是个死循环。

### 3. 关键约束被遗忘

最让我崩溃的一次：我要它逐个处理 100 个文件，每个都要严格走完"提取→校验→落库"。结果跑到第 30 个，它开始"偷工减料"——某些文件直接跳过校验就落库了。

为什么？因为**执行链路太长，模型的注意力分散了**。开头记得的约束，到后面全忘了。

### 4. 经验无法沉淀

好不容易调好一个能稳定跑通的复杂 Skill，结果它"长"在了一大段 Prompt 里。想删掉几个分支？不敢。想复用某个环节？没门。想分享给同事？人家根本看不懂。

那一刻我意识到：**我一直在用"写 Prompt"的方式，试图解决一个"流程工程"的问题。** 这从一开始就跑偏了。

---

## 二、转折：我看到了一个"反直觉"的项目

就在我准备放弃的时候，刷到一个开源项目，名字很直白——叫 **fsm-to-skill**。

官网一句话就把我震住了：

> **让大模型回归"推理"本职，将"流程控制"交还给经典而严谨的有限状态机（FSM）。**

"流程是流程，推理是推理"——这句话简直像一盆冷水泼在我脑袋上。

对啊！我为什么要让一个擅长"推理"的大模型，去记忆和执行一套"确定性流程"呢？这是它最不擅长的事啊！

FSM，有限状态机，这是计算机科学里最古老、最经典、最严谨的东西。它天生就是干"流程控制"的。**为什么不把流程交给状态机，让模型只负责"每一步的推理"？**

这个项目就是干这个的：**完全本地运行的一个工作流编排工具**——纯前端画布 + Python 后端引擎。你拖几个节点，连几条线，把流程画出来，跑通后一键导出成标准 Skill，给任何支持命令行交互的 Agent 用。

---

## 三、它的核心思路：把控制权交还给状态机

我花了一个下午把它的文档翻完，越看越觉得它的设计很"戳心"。它把流程拆成了 7 种节点，覆盖了几乎所有编排场景：

| 节点 | 它干嘛的 |
| --- | --- |
| **start** | 工作流的入口，声明初始变量 |
| **code** | 跑一段 Python 代码，输入输出都是变量 |
| **llm** | 渲染一段 Prompt，作为"出口"把消息返回给 Agent |
| **if** | 条件分支，走 A 还是走 B |
| **for** | 循环，对列表逐项迭代 |
| **aggregate** | 汇总——字符串拼接、数值求和、列表连接、字典合并 |
| **end** | 结束节点，命中就整个流程终止 |

看到这我恍然大悟：**这不就是把我那几百行 Prompt，拆成了一步步确定性的"图纸"吗？**

关键的设计在于它怎么处理"模型"这个角色：

- 每个 **Code 节点**，是 Agent 输入进入流程的**入口**；
- 每个 **llm / Prompt 节点**，是流程输出返回 Agent 的**出口**。

也就是说，模型不用再"背"一整条流程了。它只需要：**走到这一步 → 推理这一步 → 把结果交给状态机 → 状态机决定下一步走哪 → 再推理下一步**……

流程的顺序、分支、循环、结束，全部由状态机"铁面无私"地把控。**模型只做它最擅长的事——每步的推理。**

这样一来，之前那些"偷懒"、"跳过步骤"、"忘掉约束"的毛病，从根本上就堵死了——**因为流程根本不在模型手里，模型想跳也跳不了。**

## 四、怎么用？三步走，挺简单

光说不练假把式。我把它的上手流程跑了一遍，其实很简单，就三步。

### 第一步：跑起来

```bash
git clone https://github.com/xu10311737/fsm-to-skill.git
cd fsm-to-skill
pip install -r requirements.txt
python run.py
```

浏览器自动打开 `http://localhost:8000`。

### 第二步：拖节点，画流程

在画布上，把左侧的节点拖进来，点节点的 `+` 拖一条线连到下一个节点。就像画流程图一样。

然后把每个节点配好参数：

- **code 节点**：写一段 Python，入口统一叫 `main(params)`，返回一个字典就自动变成输出变量：

```python
def main(params):
    value = params["arg-1"]
    return {
        "result": value.upper(),
        "length": len(value),
    }
```

- **llm 节点**：写 Prompt 模板，里面可以用 `{{ 变量 }}` 引用前面步骤的产出。

画完点一下"校验"，它会自动检查有没有环、是不是单入口、变量能不能追溯、类型匹不匹配……**写错了它直接告诉你哪个节点有问题**，这一点对我这种粗心的人特别友好。

### 第三步：调试 + 一键导出

切到"运行"页，填上开始节点声明的输入变量，点 ▶ 运行。这时候最爽——**它能连真实的 LLM 实时跑**，节点四色标识：

- 🟠 橙 = 运行中
- 🟢 绿 = 成功
- 🔴 红 = 失败
- ⚪ 灰 = 跳过

还能看每个节点的 Prompt、思考过程、stdout/stderr、Token 用量、变量快照。**哪一步跑偏了，一目了然。**

跑通之后，点"导出 SKILL"，它会生成一个完整的 Skill 目录：

```
my-skill/
├── SKILL.md              # 说明文档
├── agent_interface.json  # Agent 到 Code / Prompt 的路由表
├── workflow.yaml         # 工作流定义
├── inference/            # LLM 提示词模板
└── scripts/              # Code 脚本 + 自动生成的 main.py 状态机入口
```

最妙的是那个 **`scripts/main.py`**——它是**一个自包含的状态机线程**。Agent 调用它，只需要一条命令：

```bash
python main.py --task-id task-001 --step-id code-1 --step-param '{"arg-1":"hello"}'
```

- `--task-id`：标识同一次任务；
- `--step-id`：这次输入要进入哪个 Code 节点；
- `--step-param`：入参 JSON。

状态机会接管整个 DAG，一直跑到遇到 Prompt 出口，把渲染好的字符串返回给 Agent。**Agent 下一次输入，再从一个 Code 节点进来。** 一来一回，就把一条完整流程"接力"跑完了。

而且它**完全本地**，数据、密钥都只在本机，没有云端依赖。对于我这种对隐私敏感的人，这一点很加分。

## 五、我的真实感受

用了一段时间，最大的感受是：**终于不用再跟一个"记不住流程"的模型吵架了。**

以前是"写 Prompt 求它"，现在是"画流程指挥它"。确定性的东西交给状态机，每步的思考交给模型，各司其职。Skill 也从一个"黑盒大 Prompt"，变成了一个**可看、可改、可版本化、可分享的工程资产**。哪天流程要改，我直接在画布上拖一拖节点就行，再也不用在一大段 Prompt 里大海捞针了。

顺带一提，它还带了一个 `trans-fsm-skill` 的转换工具——**可以把你已经写好的复杂业务 Skill，自动转成符合它标准的状态机 Skill 包**。对于手里已经有一堆存量 Skill 的人来说，这简直是迁移神器。

如果你也在被复杂 Skill 的"流程失控、维护爆炸、约束遗忘"折磨，真心建议去试试这个项目，体验一下"把控制权交还给人"的踏实感。
