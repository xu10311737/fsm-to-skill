fsm to skill 使用文档

fsm to skill 是一个完全本地运行的工作流编排工具：在画布上以 DAG（有向无环图）方式组合 Code / LLM / 条件 / 循环 / 聚合节点，调试运行后一键导出为可被任意 LLM Agent 使用的 Skill 包。状态机是唯一流程控制器，LLM 只负责推理输出。

一、快速开始

  1. 在「配置」中填写 LLM 服务商的 base_url 与 api_key，设置默认模型；如需运行 Code 节点可指定 Python 路径。
  2. 在编辑页画布中编排节点：点击或拖拽左侧组件到画布；点击节点右侧 + 追加后继节点，拖拽 + 到目标输入端口建立连线。
  3. 选中节点，在右侧配置面板完成配置；工具栏「校验」随时检查结构错误。
  4. 切到「运行」页，填写开始节点声明的输入变量，点击 ▶ 运行。
  5. 运行通过后，「导出 SKILL」生成 Skill 目录。

三、节点类型

1. 开始节点（start）

每个工作流恰好一个，是整个 DAG 的入口。Start / End 节点不在右侧配置面板编辑；初始变量通过画布左上角「新增初始变量」维护，运行前需逐一填写。支持类型：string / int / float / list / dict。

2. Code 节点

在独立子进程中执行 Python 代码。输入采用 argparse 风格参数 schema（参数名称、描述、类型、是否必填），外部 JSON 参数统一使用连字符命名，例如 arg-1；Python 代码统一定义 main(params)，并通过 params["arg-1"] 读取输入。返回值必须是字典，字典 key 会自动成为输出变量名：

def main(params):
    value = params["arg-1"]
    return {
        "result": value.upper(),
        "length": len(value),
    }
  • 输出：由 return {...} 的字典 key 自动解析，可有多个输出；类型可在面板中调整，类型不匹配视为节点失败。
  • 超时：超时按失败处理。
  • 错误分支：勾选后节点多出唯一 error 出边，失败时沿 error 边进入 Prompt 节点，并产出 <节点ID>-error-type / <节点ID>-error-message 两个变量。
  • 单节点调试：配置面板底部只有一个「单节点调试」按钮；首次调试弹框输入参数，之后使用缓存入参直接运行。

3. Prompt 节点

根据模板渲染 Prompt，模板使用 Jinja2 语法：{{ 变量名 }}。在提示词输入框中键入 / 可弹出变量列表快速插入。Prompt 节点不在 DAG 引擎内调用模型、不产出 DAG 变量，只作为 Agent 出口返回消息；调试页收到该 Prompt 后再交给配置的大模型。

4. IF 节点

条件分支：可添加多条 IF 条件，并用 AND / OR 组合；每条条件包含变量、运算符（包含 / 不包含 / 开始是 / 结束是 / 是 / 不是 / 为空 / 不为空）与比较值（常量或变量）。节点只有 if 与 else 两条出边，未命中分支的下游会被标记为「跳过」。

5. For 节点

对列表变量逐项迭代：只需配置「列表来源」（仅可选择 list 类型变量）。点击「编辑循环体」打开子画布编排循环体（支持 Code / Prompt / IF / 聚合，不支持嵌套 For）。循环体内可使用 index（当前下标，int）、item（当前元素）、len / total（总长度）。Prompt 节点会自动追加当前轮次上下文，如 5/10。收集变量由循环体末端输出自动推导，结果组成 list 写入 <节点ID>-output。

6. 聚合节点（aggregate）

汇聚多个上游分支（例如 IF 的两个分支或 error 分支）的输出，只统计成功的上游。按输出类型聚合：string 换行拼接、int/float 求和、list 连接、dict 合并。输出为 <节点ID>-output。

7. 结束节点（end）

任一结束节点被命中，整个工作流立即终止。适合在错误处理分支末尾提前收尾。

四、变量系统

  • 变量按 DAG 上游路径传导，节点只能引用自身上游可达节点产出的变量；IF / ELSE 分支未经过的变量不会被视为当前节点可用。
  • 同名变量只能由一个节点产出一次；系统默认提供全局变量 task-id，初始变量不能与其重名。
  • 变量名由字母开头，可含字母、数字、下划线和连字符（保留字如 result 等不可作为输出名，系统自动产出的 <id>-output、task-id、index、item、len、total 除外）。
  • 模板引用带连字符的变量（如 for-1-output）时可直接书写 {{ for-1-output }}，系统自动适配。
  • 类型检查宽容 null：值为 None 时视为通过。

五、校验

工具栏「校验」按钮实时显示错误 / 警告数。导出 SKILL 前必须通过全部 Error 级校验（无环、单开始、变量可追溯、类型匹配、无嵌套 For 等 19 项）。点击校验按钮打开报告，可一键定位问题节点。

六、运行与调试

  • 输入：调试页底部只有一个消息输入框；开始节点声明的初始变量使用编辑页默认赋值参与运行，list / dict 默认值请填 JSON。
  • 实时状态：节点四色：橙=运行中，绿=成功，红=失败，灰=跳过；点击节点在「节点详情」中查看 Prompt、思考过程、stdout/stderr、错误与产出变量。
  • 对话区：流式展示 LLM 输出与节点执行进度。
  • 统计：总耗时、各状态节点数、LLM 调用次数与 Token 用量、变量快照。
  • 日志：全部引擎事件流，可「导出日志」为 UTF-8 文本（不含 API Key）。

七、导出 SKILL

校验通过后，选择目标目录一键导出：

my-skill/
├── SKILL.md          # 说明文档（入参表 / 输出 / 结构）
├── agent_interface.json # Agent 到 Code / Prompt 的路由表
├── workflow.yaml     # 工作流定义
├── inference/        # LLM 提示词模板
└── scripts/          # Code 节点脚本 + 自动生成的 main.py 状态机入口
目标目录已存在时会提示覆盖；导出失败不会残留不完整目录。

八、Agent / Code / Prompt 交互模型

scripts/main.py 是导出 Skill 的总状态机线程；每个 Code 节点是 Agent 输入进入 DAG 的独立入口，每个 Prompt 节点是 DAG 输出返回 Agent 的出口。导出时会生成 agent_interface.json 用于标识路由：

{
  "main_thread": "scripts/main.py",
  "entries": [
    {
      "entry_id": "code-1",
      "node_id": "code-1",
      "direction": "agent_to_code",
      "input_schema": [
        {"name": "arg-1", "description": "输入参数", "type": "string", "required": true}
      ],
      "return_keys": ["result", "length"]
    }
  ],
  "exits": [
    {
      "exit_id": "llm-1",
      "node_id": "llm-1",
      "direction": "prompt_to_agent",
      "next_code_entries": []
    }
  ],
  "agent_envelope": {
    "agent_command": "python main.py --task-id <task-id> --step-id <code_node_id> --step-param '<json_string>'",
    "task-id": "<task-id>",
    "step-id": "<actual_code_node_id>",
    "step-param": {"arg-1": "value"}
  }
}

Agent 调用时执行 python main.py --task-id task-001 --step-id code-1 --step-param '{"arg-1":"hello"}'，用 --task-id 标识同一次任务、用 --step-id 标识本次输入要进入哪个 Code 节点；状态机继续执行 DAG，直到遇到 Prompt 出口并把渲染后的字符串返回给 Agent。在线调试会使用当前 Python 解释器生成可执行命令；导出 Skill 后可按目标系统替换为 python3。正常 Prompt 末尾会动态附加 task-id、下一步待执行命令与入参说明；Code error 分支产生的 Prompt 不附加下一步 schema。

九、配置说明

配置项说明
providers.openai / compatible / anthropic服务商 base_url 与 api_key；compatible 用于 OpenAI-compatible 私有网关
default_provider / default_modelLLM 节点默认使用的服务商与模型
timeout_seconds / max_retries请求超时与网络错误重试次数（4xx 不重试）
stream是否流式输出
python_pathCode 节点执行用的 Python 解释器路径，留空用当前环境
idle_timeout / max_task_runtimeAgent 等待下一次 shell 调用的空闲超时与整个 task 生命周期上限
shell_tool是否允许大模型调用本地 shell / bash / PowerShell 工具执行下一步 Code 命令
api_key 仅保存在本地配置文件中；界面回显为 ****** 时提交不会覆盖已保存的密钥。
保存 / 打开工作流默认使用本机系统文件窗口并保存为 YAML；导出 SKILL 时选择导出父目录，系统会按工作流名称生成 Skill 文件夹。
